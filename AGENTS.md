# REI development coordination

Read DEVELOPMENT_HANDOFF.md and the dated sections of IMPLEMENTATION_STATUS.md before changing the conversation path. Preserve existing user instructions and user changes.

## Shared development record

The user requested continuing development status records in Synapse Connect. At meaningful milestones (start of a work package, implementation, measurements, failures, blockers, completion), record the owner, purpose, changes, commit, verification, unverified limitations, and next action using the available Synapse skill and connector.

Discover permitted groups and follow the skill's destination and ingestion verification rules. Do not expand access or invent a development group. Include a concrete source reference. Do not copy company source bodies, credentials, private group IDs, or screenshots into public artifacts. If the connector is unavailable, mark the milestone as not yet shared locally; do not claim it was sent.

Do not infer permission for Chatwork posting or autonomous task restart from this record rule. Keep notification frequency to meaningful changes. Coordinate boundary files and runtime deployment before parallel changes; avoid duplicate model processes and conflicting use of live data.

## Chatwork destination verification

Use a dedicated reporting tab for authorized development reports. Immediately before filling and sending, verify the current room URL/ID and exact room heading against the authorized destination. A previously selected tab can change rooms while development runs; do not rely on its earlier snapshot. Verify the posted message in the same room after sending. If a wrong-room post occurs, disclose it, correct its text where possible, resend to the authorized destination, and record the failure and recovery without claiming the original send was successful.
